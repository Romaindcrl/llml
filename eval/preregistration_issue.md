# Pre-registered evaluation plan — public benchmarks

> **Status: PRE-REGISTRATION.** This issue freezes the evaluation plan for LLML on
> public, standard benchmarks *before* any official run. Every subsequent deviation
> will be documented in comments on this issue — never silently. Methodology doc:
> [`eval/CDC_EVAL_LLML.md`](../blob/claude/runpod-deployment-setup-4rvggq/eval/CDC_EVAL_LLML.md) ·
> decision journal: [`AGENTS.md`](../blob/claude/runpod-deployment-setup-4rvggq/AGENTS.md).
> Frozen LLML commit: `131527d1b52d0e8c2054e09e4e0f60b34a7b2815` (branch `claude/runpod-deployment-setup-4rvggq`,
> includes the CUDA port `m0/hf.py` / `m0/d2l_hf.py` used for all runs).

## 1. Claims under test

- **Claim A — weight-memory works.** A document internalized into a LoRA adapter via
  LLML's `/sleep` pipeline is recallable with fidelity comparable to having the
  document in context, at lower inference cost (prompt tokens, VRAM, latency).
- **Claim B — the system degrades nothing.** (B1) With the domain router active,
  scores on standard benchmarks are statistically equivalent to the base model.
  (B2) An adapter forced always-on *does* degrade those scores (public replication of
  the internal −84 pt HumanEval hazard, benchmark #19 / BENCHMARKS §17).
  (B3) Repeated `/sleep` cycles cause no measurable catastrophic forgetting —
  **registered as an OPEN hypothesis**: no internal benchmark measured multi-cycle
  forgetting; the README's gate/rollback is a mechanism, not a measurement.
- **Claim C (secondary) — the verify loop yields a real gain.** The repo's HumanEval
  92→98 delta was measured on the **first 40 problems only** with a homemade harness
  (more lenient PRELUDE, ±2.5 pt/item granularity). It is re-measured here on
  EvalPlus, all 164 problems, with CIs, before being cited anywhere.

## 2. Experimental matrix (frozen)

**Models** (exact HF checkpoints; revision hashes recorded at load time):

| ID | Checkpoint | Role |
|---|---|---|
| M1 | `Qwen/Qwen2.5-7B-Instruct` | primary (LLML's current base) |
| M2 | `Qwen/Qwen2.5-14B-Instruct` | intra-family size comparison |
| M3 | `meta-llama/Llama-3.1-8B-Instruct` | second family (gated) |
| M4 | `google/gemma-2-9b-it` | third family / hardest fine-tuning stress test |

Deliberately excluded (documented, not negotiable mid-run): reasoning models,
MoE, -Coder variants.

**Quantization**: 8-bit bitsandbytes everywhere (mirrors LLML's 8-bit MLX setup);
one bf16 control run on M1 (Lot 1). If |bf16 − 8-bit| > 2 pts on any benchmark, it
is flagged explicitly.

**Configs**: C0 = base model alone · C1 = full LLML (router active, adapters
on-demand) · C2 = adapter forced always-on (router off) · C3 = RAG-only (Claim A
only) · C4 = full document in prompt (Claim A honest baseline).

**Hardware/software**: RunPod RTX 4090 24 GB, CUDA 12.4, torch 2.4.1;
transformers 4.46.3 · peft 0.13.2 · bitsandbytes 0.44.1 · lm-eval 0.4.5 ·
evalplus 0.3.1 (full pins: `eval/requirements.lock`). Greedy decoding
(temperature=0) wherever the harness permits; otherwise seeds 42/1337/2026,
mean ± sd. No homemade harness anywhere: lm-eval-harness + EvalPlus only.

**LoRA (CUDA port of the MLX recipe)**: r=16, α=20·r (MLX scale-equivalence),
last 8 layers, target modules `q,k,v,o,gate,up,down_proj`, lr 5e-5, batch 1,
chat format, anchor rehearsal + held-out acquisition gate (0.45) + rollback —
`m0/d2l_hf.py`, hyperparameters logged per run.

## 3. Benchmarks & assignments

| Benchmark | Tool | N | Configs | Models |
|---|---|---|---|---|
| HumanEval+ | EvalPlus | 164 | C0, C1, C2 | M1–M4 |
| MBPP+ | EvalPlus | 378 | C0, C1, C2 | M1, M3 |
| GSM8K (8-shot, strict-match) | lm-eval | 1319 | C0, C1, C2 | M1–M4 |
| IFEval | lm-eval | 541 | C0, C1 | M1, M3, M4 |
| MMLU-Pro (6-domain subset) | lm-eval | ~1700 | C0, C1 | M1, M3 |

**MMLU-Pro subset, drawn with seed=42 BEFORE this pre-registration and hereby
frozen** (`eval/scripts/draw_mmlu_domains.py`): **biology, business, computer
science, economics, math, other**.

**Claim A corpora (external only — nothing authored by the repo author):**
QuALITY dev split, 15 documents drawn with seed=42; plus 3 public post-2024
niche technical docs, 20 factual questions each generated by M3 (≠ Qwen family)
and human-validated before any run (mandatory checkpoint). Contamination
control: C0 must FAIL on each internalized doc's questions; docs where C0
succeeds are excluded and listed.

**Claim A tests**: internal NIAH (C1/C3/C4) · closed-book QA (C1/C3/C4/C0) ·
multi-hop QuALITY subset (C1/C4) · cost (tokens, peak VRAM, median latency,
batch=1, same machine — C1/C4).

**Claim B3 protocol**: 10 consecutive `/sleep` cycles on 10 distinct documents
(M1 and M4); re-measure GSM8K + HumanEval+ in C1 after cycles 1, 5, 10;
score = f(cycles), slope test.

**Claim C protocol**: HumanEval+ and MBPP+ on M1, C0 vs C0+verify. The report
will state explicitly that repair leans on docstring examples ("ground truth
offered" regime), and that under greedy decoding the loop performs effectively
one distinct repair.

## 4. Pre-registered quantitative hypotheses

| # | Hypothesis | Success criterion |
|---|---|---|
| H-B1 | C1 ≈ C0 on all §3 benchmarks | gap < 1 pt AND overlapping 95% bootstrap CIs (10k resamples) |
| H-B2 | C2 < C0 significantly on ≥ HumanEval+ | non-overlapping CIs; direction replicates the internal −84 pt (magnitude expected smaller on full 164) |
| H-B3 (open) | forgetting curve flat over 10 `/sleep` cycles | slope not significantly < 0 (permutation test) |
| H-A1 | C1 ≫ C0 on closed-book QA over internalized docs | non-overlapping CIs |
| H-A2 | C1 ≥ 80% of C4's score | point estimate ≥ 0.8 × C4 |
| H-A3 | C1 < C4 on all three cost metrics | prompt tokens, peak VRAM, median latency all lower |
| H-A4 (expected concession) | C3 (RAG) ≥ C1 on pure factual QA | if so, stated as-is — consistent with the README |
| H-C1 | verify > no-verify on HumanEval+/MBPP+ (M1) | CI on the paired delta excludes 0; magnitude reported vs the internal +6/40 |

## 5. Kill criteria (early stop, from the CDC §6)

- **Lot 1**: C0 baselines not reproducible within ±3 pts of published figures
  (model cards / EvalPlus leaderboard) after investigation → harness/env broken →
  stop + report.
- **Lot 3**: C1 significantly < C0 on ≥ 2 benchmarks → the central non-regression
  claim is false → the negative result becomes the report.
- **Lot 4**: C1 < 50% of C4 on closed-book QA → weight-memory fails on external
  corpora → negative result documented, not hidden.
- Global cap: 60 GPU-hours.

## 6. Known deviations & threats (declared up front)

1. **MLX → CUDA port**: all public runs use `m0/hf.py`/`m0/d2l_hf.py`
   (transformers + bitsandbytes 8-bit + peft), not the original MLX backend.
   Quantizer differs (bnb int8 vs MLX 8-bit) — hence the bf16 control run and the
   sign/gap (not exact-percentage) replication standard.
2. Adapter swap semantics differ (peft adapters stay resident; MLX reloads).
   CUDA swap latencies are reported separately and never merged with the ~2 ms
   Apple-unified-memory figures.
3. Internal benches #14–15 used a private spec and withheld scripts; public
   substitutes (synthetic tenants, public corpora) are built here — numbers are
   not 1:1 comparable. The withheld scripts are published as part of Lot 8.
4. All runs launched are reported, including failures (technical crashes are
   re-run identically and logged).
